## Границы и архитектура

Browse/search/account обслуживает модуль `innertube`; AUDIO проходит через
`CapsuleAudioEngine` → `CapsuleInnerTubeXPlayer` → закреплённую InnerTubeX `v0.5.2`
→ Media3. `MusicService` владеет очередью, кешем разрешённых URL, приоритетами
предзагрузки, восстановлением сети и передачей аудио видеоплееру. Разрешение
сериализовано `AudioResolveScheduler`; одинаковые запросы объединяет
`AudioResolveCoordinator`. Эти механизмы сохранены.

YouTube-загрузки используют Media3 DownloadIndex, отдельный постоянный download cache
и ProgressiveDownloader; player cache читается отдельно и не смешивается между форматами.
Разрешённые издателем независимые файлы сохраняются через MediaStore Downloads.

Дизайн, цвет, анимации, рекомендации, набор источников, библиотечная схема и
пользовательские настройки не менялись. В manifest добавлен тип существующей
службы WorkManager для фоновой передачи данных; уведомление использует стандартные
компоненты Android и существующий канал загрузок.

## Подтверждённые проблемы и исправления

## Клиенты и холодный старт

Закреплённые идентификаторы сохранены: `WEB_REMIX`, `VISIONOS`, `VISIONOS_0_1`,
`TVHTML5_SIMPLY`, `WEB_EMBEDDED_PLAYER`, `WEB_CREATOR`.
`VISIONOS` — версия 1.02, `VISIONOS_0_1` — версия 0.1. У них разные manifest и
ограничения; одинаковое wire-name не означает взаимозаменяемость.

Для холодного обязательного токена готовится общая фоновая сессия, а разрешение
получает Vision-профили в их пользовательском относительном порядке. При готовом
токене следующий resolver снова получает исходный порядок. Играющий трек и уже
полученные исправные URL не заменяются ради смены клиента. Готовность токена публикуется
до ожидания best-effort прогрева cipher/config: его ошибка не удерживает Vision-приоритет. Готовые вручную
настроенные токены не требуют повторного прогрева. Порядок Embedded без обязательного
токена сохраняется даже при холодном запуске.

Политика обязательных токенов берётся из `PlaybackClientCatalog`, а manifest,
идентичности клиентов, cookies, binding токенов и выданные extractor headers не
переписываются. `WEB_CREATOR` требует авторизации. Правила совместимости private
uploads и ограниченного контента сохраняются; разрешение URL не гарантирует, что
внешний сервис действительно отдаст конкретную композицию.

## Скачивание, отмена и офлайн

В зависимости от совместимости и авторизации используются те же шесть профилей;
настройка приоритетов уже существует, дополнительный экран не нужен. После
клиентского отказа применяется следующий разрешённый профиль. Бюджет одного
разрешения — три профиля; бюджет повторного открытия загрузки после 403/410 —
два перехода. Это разные уровни, а не обещание всего трёх HTTP-запросов на файл.
Внутренние запросы конфигурации/токенов и bounded-range запросы считаются отдельно.

Совместимый encoding может продолжить частичные байты; смена encoding очищает
несовместимый фрагмент перед записью. При обычной сетевой ошибке сохраняются URL и
частичный кеш. Диапазоны учитывают размер, выданный InnerTubeX. Предсуществующие
защиты same-link retry, per-media quarantine, HTTP 429 и сохранение DownloadIndex
не удалялись. Завершённый кеш доступен без нового запроса к YouTube.

Для независимых источников сохраняется разрешение издателя (`downloadable` Audius
или существующая лицензия других провайдеров); radio не превращается в скачиваемый
файл. WorkManager переживает смерть процесса, показывает стандартное уведомление с
отменой и ограничивает число запусков. Готовый MediaStore URI переиспользуется при
повторном запуске задачи; восстановленные после backup ID проверяются по UUID своей WorkManager-задачи, владельцу
и папке перед удалением. Незавершённые rows остаются pending.

## Безопасность

- BotGuard RPC использует один HTTP-клиент на minter; запросы отменяются при закрытии,
  ограничены по времени и размеру ответа. Незавершённые continuations освобождаются.
- В лог не передаётся сырой JavaScript console/error с возможными токенами;
  `PoTokenResult.toString()` скрывает содержимое.
- Новая offline-проверка допускает только HTTPS YouTube media hosts, проверяет каждый
  redirect и запрещает понижение до HTTP. Независимые redirects ограничены и каждый
  повторно проверяется как HTTPS без userinfo/fragment.
- Проверка полноты — длина и покрытие кеша, а не криптографическая сверка: исходники
  не предоставляют проверяемый checksum. При неизвестной длине гарантировать
  смысловую полноту записи по одному EOF невозможно.

Для финального security-аудита: существующий manifest разрешает cleartext всему
приложению; глобальное отключение может сломать существующие источники и здесь не
выполнялось. Backup rules не исключают основной DataStore с авторизацией. Следует
отдельно определить политику backup/переноса credentials без потери пользовательских
настроек и библиотеки. Широкая перестройка хранилища секретов в TASK 01 не выполнялась.

`6d08504262de76a4ba841dc24489a754e2f48e4f`) и InnerTune (`dev` snapshot

JDK-image cache; кеш изолирован без изменения исходников, затем проверки прошли.
Одна промежуточная ошибка компиляции нового Robolectric-теста исправлена и
проверена повторным запуском. Lint warnings не скрывались и не обнулялись baseline-файлом.

Android-устройство не подключено (`adb devices` — пусто); Android 16 не проверен.

Нельзя считать проверенными на телефоне: первый звук после установки, Wi-Fi/mobile
handoff, долгий прогон, seek, фон/возврат, audio/video и отсутствие underrun. Для этих
сценариев нужны аппаратный прогон и реальные логи. Сетевые ошибки моделируются
автоматическими тестами, они не заменяют измерение YouTube/Audius через сеть пользователя.

для него не реализовано. Существующий лимит 240 MiB независимых файлов сохранён.

с Android 10. Действительный HTTP 429 не обходится; после исчерпания retry загрузку
может потребоваться повторить вручную после окончания cooldown.

Сохранность обложек YouTube офлайн по-прежнему зависит от существующего ограниченного
Coil-кеша: при его очистке обложка может отсутствовать, даже если аудио сохранено.
Постоянное отдельное хранилище этих обложек в TASK 01 не вводилось. Debug-сборка
проверена, release/R8-сборка отдельно не запускалась.
