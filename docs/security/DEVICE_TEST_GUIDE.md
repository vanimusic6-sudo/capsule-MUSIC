# Capsule Music: совместная проверка безопасности на реальном устройстве

> Относится к PR #58 и ветке `audit/security-deep-20261028`. Это
> **не** руководство по отключению защиты телефона; не предоставляй root или
> постоянный удалённый доступ и не отправляй приватные токены.

## Что уже можно проверить автономно в GitHub

- Исходники, зависимости и известные CVE (OSV), Semgrep, mobsfscan.
- Компиляция и существующие юнит-тесты; выпуск подписанного APK.
- Проверка SHA-256, действительности сертификата **текущего** APK, package ID,
  запрета debug-флага, списка запрашиваемых разрешений.
- **Без устройства** нельзя доказать отсутствие отправки персональных данных,
  реальную безопасность WebView, восстановление очереди после обновления
  или передачу «Слушать вместе» по сети.

## Шаг 1. Получить правильную сборку

1. Открой [GitHub Actions: Release APK](https://github.com/vanimusic6-sudo/capsule-MUSIC/actions)
   и выбери успешную сборку **ветки `audit/security-deep-20261028`**.
2. Скачай `Capsule-MUSIC-Universal-Release` и `Capsule-MUSIC-Release-Security`.
3. В JSON должна быть проверенная подпись и SHA-256.
4. **До установки** сохрани текущую музыку/очередь и не используй реальный
   Discord/YouTube-аккаунт для теста сомнительных редиректов.

## Шаг 2. Подключение через ADB (только чтение)

1. В Windows установи официальные Android SDK Platform-Tools.
2. Подключи телефон USB-кабелем, включи «Параметры разработчика» →
   «Отладка по USB». Подтверди RSA-ключ только для своего ПК.
3. В PowerShell из корня исходников проекта выполни:

```powershell
adb devices
powershell -NoProfile -File .\scripts\capsule_device_report.ps1
```

4. Пришли файл `capsule-device-security.txt`.
5. Когда закончишь, отключи USB-отладку (и при необходимости
   отзови отладочные авторизации). Команды не меняют систему и не
   сохраняют журналы приложений.

Не присылай полный `dumpsys`, `logcat`, архив резервной копии, OAuth-токены,
cookie-файлы, пароли или TLS/SSL ключи.

## Шаг 3. Проверка трафика — PCAPdroid

1. Установи PCAPdroid из официального F-Droid/GitHub-релиза.
2. В приложении выбери **только Capsule Music** для захвата.
3. Начни с режима «список соединений/домены» без MITM-расшифровки HTTPS.
4. Поочерёдно проверь: холодный запуск, 1 минуту ожидания без действий,
   поиск, аудио, видео, скачивание трека, открытие библиотеки, экспорт
   резервной копии в локальный файл, работу в фоне.
5. Повтори сценарий при включённой и выключенной настройке статистики,
   если она есть. Сохрани **только домены, порты, количество запросов
   и тип сценария**, без URL с параметрами и содержимого пакетов.
6. Отдельно протестируй Together: два тестовых устройства в своей сети,
   только тестовая комната и неконфиденциальные названия треков.

**Важно:** PCAPdroid использует локальный VPN-слот Android, поэтому может
конфликтовать с действующим VPN. Не отключай необходимую защиту на чужой
сети. Вместо этого можно использовать отдельный тестовый Wi-Fi/роутер.

## Шаг 4. Контролируемые злоупотребления (только тестовые данные)

- Установка/обновление APK, проверка сохранности очереди и настроек.
- Discord и YouTube WebView — **только тестовые аккаунты**. Проверить, что
  внешний/поддельный домен не может принять завершение авторизации.
- Резервная копия с выдуманными данными: в XML архива не должны встречаться
  фиктивные значения полей cookie/token. Не загружай настоящие backup ZIP.
- Импорт неполных CSV/M3U/ZIP в тестовом профиле: отсутствие зависаний,
  ложного восстановления и удаления чужих файлов.
- Together на двух устройствах: вход, отключение/повторное подключение,
  неверный ключ, длинные имена. **Текущий LAN ws:// не шифрует трафик**;
  не тестируй его в публичной сети.

## Шаг 5. Как передать результаты мне

В этом чате можешь приложить:
- `capsule-device-security.txt`;
- обезличенный список соединений PCAPdroid по сценариям;
- скриншоты тестового интерфейса и сообщения об ошибках **без токенов**;
- текстовый отчёт MobSF о **публичной** подписанной APK, если проведёшь
  локальный динамический анализ без личных аккаунтов.

Я сопоставлю отчёты с кодом и GitHub Actions и внесу исправления в PR.
**Прямого подключения к ADB/локальному телефону через этот чат нет.**
Если у тебя доступен режим ChatGPT Work с компьютером, можно использовать
его для работы с графическим интерфейсом, но прямой ADB всё равно зависит
от доступных ему разрешений и инструментов. Не обещаю контроль телефона,
который среда явно не предоставляет.

## Критерии остановки и нерешённые риски

- Любое неожиданное сетевое соединение требует анализа назначения, но
  сам неизвестный домен не равен доказательству утечки.
- LAN «Слушать вместе»: `ws://` без шифрования не годится для
  конфиденциальных комнат в чужой сети. Для полноценного устранения
  нужен новый протокол/TLS плюс совместная проверка нескольких устройств.
- Последовательность входа Discord использует legacy scraping;
  переход на OAuth 2.0 PKCE требует регистрации приложения и согласования
  redirect URI с владельцем интеграции.
- Без реального устройства динамические HTTP/TLS-потоки, WebView и backup
  нельзя честно пометить как «проверено».
